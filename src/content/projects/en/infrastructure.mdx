# Infrastructure: self-hosted services managed as code

## The problem

I host services for my family and friends: cloud storage, a password manager, messaging, a media server, home automation, document management and business software. Installing an application on a server is easy; keeping several dozen of them up to date, reachable and secure over the years is the hard part.

The goal is to make every service **reproducible from a Git repository**, on more than one machine, without keeping secrets in public files.

## Architecture

The infrastructure runs on two main servers: a **TrueNAS** server and a **cloud VPS**. The inventory assigns each service to a host, so moving a service means changing one group. Each service has its own folder with an Ansible playbook, a Docker Compose file and the templates it copies. Other playbooks prepare the hosts and manage one **Cloudflare** DNS zone each.

Monitoring runs on the VPS: **VictoriaMetrics** collects metrics from both Traefik instances, the TrueNAS server being reached over the **Netbird** VPN, and **Grafana** raises alerts on server errors, high latency and unreachable targets.

## Technical choices

- **Secrets outside the public repository.** Sensitive values live in a private submodule encrypted with Ansible Vault.
- **Hardened Ansible access.** Ansible connects with a dedicated account that only accepts an SSH key from allowed networks. The bootstrap playbook disables password and root logins, and refuses to run from any other network.
- **Single sign-on.** **Zitadel** is the identity provider; the OIDC applications of services managed outside Ansible are declared and provisioned with OpenTofu.
- **Narrow replication rights.** Each replication client gets an account limited to one command that starts a TrueNAS replication task, so the TrueNAS API key never leaves the server.
- **Checks before changes.** Common tasks lint the YAML, the playbooks and the Compose files, test roles with Molecule, and preview changes without applying them.

## Results

The repository lists more than forty services, including Nextcloud, Vaultwarden, Jellyfin, Home Assistant, Paperless-ngx, Matrix Synapse, Gitea and the Mini Train Store Odoo instance. It also hosts tools for my other projects, such as the Tolgee translation platform used by Xila.

## Limitations

Two deployment models coexist: some services run as TrueNAS Apps, others are deployed by Ansible, and the two do not share the same lifecycle. TrueNAS also manages its own users and SSH settings, so the playbooks can only check them there. Monitoring detects failures, but it does not replace testing restores.
