# Mini Train Store : une boutique en ligne pour un commerce familial de trains miniatures

## Le problème

Le commerce de trains miniatures de mon père vendait en partie par des annonces publiées sur Leboncoin. Une boutique en ligne indépendante devait proposer les mêmes produits, avec des paiements, des expéditions et des factures qui fonctionnent seuls, pour un vendeur peu à l’aise avec l’informatique.

La première version de la boutique tournait sur une instance **Odoo** auto-hébergée. Elle fonctionnait, mais elle était lourde à exploiter et lente à faire évoluer. Je l’ai remplacée par une boutique plus légère, construite sur **Vendure**, un moteur de commerce en ligne open source configuré en code, et j’ai gardé une **extension de navigateur** pour la partie propre au commerce : sortir les annonces de Leboncoin.

## Architecture

Le **serveur** répond aux API GraphQL de la boutique et d’administration, et sert le tableau de bord. Le **worker** tourne depuis la même image et gère les e-mails, les factures PDF et l’index de recherche avec la file de tâches de Vendure, qui vit dans la base : pas besoin de Redis à cette échelle. La **vitrine** est une application Next.js qui ne parle qu’à l’API de la boutique. Les paiements passent par **Stripe** (carte et PayPal), et les colis par les points relais **Mondial Relay**, ou bien les clients les retirent en magasin.

L’**extension** est construite avec **WXT**, **Vue 3**, Tailwind CSS et TypeScript. À l’ouverture d’une page de profil Leboncoin, son script de contenu extrait les annonces sans aucun clic. Le script d’arrière-plan les enregistre dans le stockage local du navigateur, séparément pour chaque profil, et fusionne les nouveaux résultats avec ceux déjà enregistrés. La fenêtre de l’extension trie les annonces par date ou par prix et les filtre par statut (active, vendue, retirée).

## Choix techniques

- **N’écrire que ce qui n’existe nulle part.** Le cœur de Vendure et des plugins maintenus couvrent le catalogue, les paiements, les e-mails et les factures. Le code maison couvre les frais de port par grille de poids, le paiement au retrait et la migration.
- **Garder le code maison hors du chemin critique.** Une panne d’un plugin maison ne doit jamais bloquer une commande.
- **La configuration dans Git, le catalogue dans la base.** Plugins, champs personnalisés, taxes, modèles d’e-mails et de factures sont versionnés et relus en pull request ; produits et commandes vivent dans la base de Vendure.
- **Migrer plutôt que repartir de zéro.** Des scripts transforment la base Odoo en CSV pour l’importeur officiel de Vendure : annonces avec leurs photos, marques, échelles et compagnies normalisées, clients, commandes passées avec leurs factures, et redirections depuis les anciennes adresses.
- **Livrer des images.** Chaque pull request vérifie le lint, les types, les tests, les migrations et les deux images Docker. Sur `main`, les images sont publiées et release-please tient à jour une pull request de version.

## Résultats

La boutique est en ligne sur **[minitrainstore.fr](https://www.minitrainstore.fr/)** et tourne sur mon infrastructure auto-hébergée. L’extension et l’identité visuelle, comme le logo et les cartes de visite, sont des dépôts publics ; le dépôt de la boutique reste privé, car il contient la configuration du commerce.

## Limites

L’extraction dépend du HTML de Leboncoin : un changement de son côté peut casser les sélecteurs, donc le code d’analyse doit rester court et facile à corriger. Les annonces sont stockées dans le stockage local d’un seul navigateur et ne sont pas partagées entre appareils. Les ventes ne sont pas encore synchronisées entre Leboncoin et la boutique.
